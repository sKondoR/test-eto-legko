# Замер скорости скачивания

Консольный скрипт на Node.js + TypeScript. Он делает 10 последовательных запросов к одному адресу и печатает:

- время каждого запроса;
- среднее время запроса;
- общий объём скачанных данных;
- скорость скачивания.

## Требования

- Node.js 24 или новее. Node запускает `.ts` напрямую, сборка не нужна.

У скрипта нет runtime-зависимостей. Для запуска `npm install` не нужен.

## Запуск

```sh
node src/cli.ts <url>
```

или

```sh
npm start -- <url>
```

Пример:

```sh
node src/cli.ts "https://speed.cloudflare.com/__down?bytes=5000000"
```

```
Скачиваю https://speed.cloudflare.com/__down?bytes=5000000 10 раз подряд...
Запрос  1/10: 2407.7 мс, 5.00 МБ
Запрос  2/10: 2226.9 мс, 5.00 МБ
Запрос  3/10: 780.7 мс, 5.00 МБ
...
Запрос 10/10: 698.3 мс, 5.00 МБ

Запросов:            10
Среднее время:       1059.5 мс
Скачано всего:       50.00 МБ
Скорость скачивания: 37.75 Мбит/с (4.72 МБ/с)
```

Во время каждого запроса в терминале видна строка прогресса. Её сменяет итоговая строка запроса:

```
Запрос  3/10: ▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░  2.61 / 5.00 МБ  52%  38.40 Мбит/с
```

Если сервер не прислал `Content-Length` или сжал ответ, полосы и процентов нет: видны только скачанные МБ и текущая скорость. При выводе в файл или pipe прогресс не печатается.

Адрес должен начинаться с `http://` или `https://`. Если адреса нет, он некорректный, сервер вернул статус не 2xx или больше 30 секунд не присылал данные, скрипт печатает ошибку в stderr и завершается с кодом 1.

## Единицы и формулы

Все единицы десятичные, как у провайдеров и Speedtest:

| Величина             | Единица | Значение                           |
| -------------------- | ------- | ---------------------------------- |
| Время                | мс      | миллисекунды                       |
| Объём                | МБ      | 1 МБ = 1 000 000 байт              |
| Скорость             | Мбит/с  | 1 Мбит/с = 1 000 000 бит в секунду |
| Скорость (в скобках) | МБ/с    | 1 МБ/с = 1 000 000 байт в секунду  |

Формулы:

```
среднее время = суммарное время 10 запросов / 10
скорость      = общий объём × 8 / суммарное время 10 запросов
```

Скорость считается по общему объёму и общему времени, а не как среднее из скоростей отдельных запросов. Так долгий запрос не теряет свой вес в итоге.

## Как идёт замер

1. Время запроса — от вызова `fetch` до прочтения последнего байта тела. В него входят DNS, установка соединения, ожидание ответа и скачивание.
2. Объём — только байты тела ответа, без HTTP-заголовков. Тело читается потоком и не хранится в памяти.
3. Скрипт шлёт заголовок `Accept-Encoding: identity` и просит ответ без сжатия. Тогда счётчик видит те же байты, что пришли по сети. Если сервер всё равно сжал ответ кодировкой, которую знает `fetch` (gzip, deflate, br, zstd), `fetch` распаковывает тело сам, и объём считается после распаковки. В этом случае скрипт печатает предупреждение в stderr: скорость сети завышена.
4. Запросы идут строго по очереди: следующий начинается после полного ответа на предыдущий.
5. `fetch` держит соединение открытым (keep-alive). Первый запрос открывает TCP/TLS-соединение и обычно длится дольше, а запросы 2–10 используют его повторно.
6. Скрипт не меняет адрес. Если файл лежит в CDN, первые запросы могут быть медленнее, пока файл не попал в кэш ближайшего узла.
7. Таймаут — 30 секунд простоя. Запрос обрывается, если сервер столько времени не присылает ни заголовков, ни очередного куска тела. Общего лимита на длительность запроса нет, поэтому тяжёлый файл на медленном канале скачивается до конца.

Для честного результата берите тяжёлый файл (несколько мегабайт и больше). На лёгком файле время установки соединения и ожидания ответа занимает большую долю, и скорость выходит ниже реальной.

## Разработка

```sh
npm install         # dev-зависимости: typescript, vitest, oxlint, oxfmt
npm test            # юнит-тесты и тесты на локальном HTTP-сервере, интернет не нужен
npm run test:live   # живой тест на реальном адресе в интернете
npm run check       # проверка типов + линтер + формат + тесты
npm run format      # отформатировать код
```

Живой тест по умолчанию скачивает 10 раз по 5 МБ с `speed.cloudflare.com`. Адрес можно заменить переменной `LIVE_URL`:

```sh
LIVE_URL="https://example.com/big.jpg" npm run test:live      # bash
$env:LIVE_URL="https://example.com/big.jpg"; npm run test:live # PowerShell
```

Структура:

```
src/speedtest.ts  – запросы и расчёт итогов
src/format.ts     – единицы и строки вывода
src/cli.ts        – разбор аргумента, печать, коды выхода
test/             – юнит-тесты и тесты CLI
test/helpers/     – локальный HTTP-сервер и запуск CLI для тестов
test/live/        – живой тест
```
